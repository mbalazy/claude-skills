# WebDriverAgent

Read when WebDriverAgent will not come up, when you create or hand over a simulator, or when you touch the pinned WDA version.

- **`scripts/wda-device.sh`** - brings WebDriverAgent up on a physical iPhone (and reports or stops it); the one piece of the phone's plumbing that cannot be automatic.
- **`scripts/wda-sim.sh`** - the simulator counterpart: `status <udid>` (installed / absent / could not inspect), `source <udid>` (a checked runner bundle to install), `build` (builds one from appium-webdriveragent when none exists), and the readiness gate `ensure <udid> --port <p>` - installs the runner if absent, starts it on `<p>` and prints `WDA READY` only after the listener is attributed to `<udid>` and `elements --all` came back through it. A simulator created or assigned for a run passes `ensure` before handoff; `RIG OK` is the separate app/JS proof and says nothing about WDA. `check` is the same proof without installing or starting anything.
- **WDA version is pinned**: both `wda-sim.sh` and `wda-device.sh` fetch `appium-webdriveragent@$WDA_VERSION` (default 16.18.5; unpinned, npm hands out 17.x, which wants Node 22/24/26+). Against 16.17.10 on an iPhone 17 simulator (2026-11-17, 5 rounds each): `findElements` with 134 matches 5.5 s -> 0.44 s and with 20 matches 0.74 s -> 0.13 s; `elements`, `el`, `waitid` and `screenshot` unchanged; `regress.sh` output identical apart from session ids and `waitid` fitting one more poll into its second. A sources checkout of another version (`~/.cache/wda-device/package`) is never replaced by the scripts - they print a NOTE saying how to switch.
- **The phone keeps its keyboard settings**: upstream WDA switches Auto-Correction and Predictive Text OFF in the phone's own settings on every start and never restores them, so `wda-device.sh` builds the phone's runner from `~/.cache/wda-device/package-device`, a copy with that call removed (simulators still use upstream's behaviour). Consequence: on the phone autocorrect may change words typed with `type` - use `typeid`, which reads the field back and fails on any change. `WDA_KEEP_KEYBOARD=0` restores upstream's behaviour.

## When it will not start

If WDA won't come up (`sim-ui.sh` errors on `ensure_wda`), read its diagnostics first - they are a fix, not a fallback. They say first whether `com.facebook.WebDriverAgentRunner.xctrunner` is installed on the target: when it is NOT, they print a checked `xcrun simctl install <udid> <bundle>` (or, with no usable bundle anywhere, `scripts/wda-sim.sh build`), and `scripts/wda-sim.sh ensure <udid> --port <p>` does install + start + proof in one step. "Could not inspect" is reported as that, never as missing. Only for an installed runner that still fails do they add window advice, and only where Simulator.app exists on the Mac, as a possible cause: on Xcode 26 and earlier a sim with no Simulator.app window refused the runner (`XCTest 10300`); Xcode 27 ships no Simulator.app and WDA starts on a headless sim there. Only then fall back: the visual loop still works with plain simctl:
```
xcrun simctl io booted screenshot /tmp/sv.png
```
then Read the PNG. You lose the element tree and tap control (observe-only), but screenshot + Read is enough for a visual compare loop. Lifecycle commands (`launch`/`relaunch`/`terminate`/`openurl`/`screenshot`) never need WDA. On a physical iPhone the fallback is the same (`sim-ui.sh screenshot` goes through devicectl and needs no WDA), and the fix is `scripts/wda-device.sh <udid> --status` / a fresh `wda-device.sh <udid> --team <id>`. (`mobile-mcp`, the old fallback, is gone: `history.md`.)

- **WebDriverAgent ports belong to a simulator, and the assignment changes between sessions.** Any WDA answering on `WDA_PORT` will happily serve a tree from ITS device, so a stale port number in `config.md` used to produce a confident description of the wrong screen. `sim-ui.sh` now compares the port's owning device against `SIM_UDID` (CoreSimulator runs simulated processes out of `.../Devices/<UDID>/...`, so `lsof -ti tcp:PORT` plus `ps -o command=` answers it) and refuses on a mismatch, naming the port that does serve your device. Start a runner on a free port with `SIMCTL_CHILD_USE_PORT=<port> xcrun simctl launch <udid> com.facebook.WebDriverAgentRunner.xctrunner`.
- **A freshly created simulator has no WebDriverAgent runner at all.** `simctl create` gives a device with only the system apps; an unattended run on 2026-09-28 found that out mid-way, when `sim-ui.sh` could not launch `com.facebook.WebDriverAgentRunner.xctrunner` on a sim that had been created for the run and proven only with `RIG OK`. Run `scripts/wda-sim.sh ensure <udid> --port <free port>` on every simulator you create or hand to a run: it installs a checked runner bundle (a runner already installed on another simulator with the same iOS runtime, found at run time - the container path differs per simulator and per install, so never copy one from notes), starts it and proves it. Copying a runner between simulators is verified for the same runtime (iOS 26.2, 2026-09-28/29); another runtime stays unproven until `ensure` prints `WDA READY`.
- **Window advice for WDA is conditional, not a rule.** On Xcode 26 and earlier WDA refused a simulator with no Simulator.app window (`XCTest 10300, failed to background test runner`, 2026-08-11): a sim booted by `simctl boot` while Simulator.app was closed, or created fresh and never opened. Xcode 27 ships no Simulator.app (`open -a Simulator` fails: "Unable to find application named 'Simulator'"), and WDA started on headless sims there (2026-09-28/29). So `sim-ui.sh` prints window advice only for an INSTALLED runner that failed, only when Simulator.app exists on the Mac, and as a possible cause: `open -a Simulator --args -CurrentDeviceUDID <udid>` when Simulator.app is not running, `xcrun simctl shutdown <udid> && xcrun simctl boot <udid>` when it is (a running Simulator.app ignores `--args` - verified 2026-08-20 - but opens a window for every device booted while it runs). The booted COUNT is not a cause on its own - three windowed sims hosted WDA fine on 2026-08-20 - so the error lists the booted devices as context only.
- **A WDA answering on the default :8100 is evidence only about its own simulator.** `sim-ui.sh` attributes it before saying anything: the target's own runner there means it was launched without the `SIMCTL_CHILD_USE_PORT` prefix; another simulator's runner there says nothing about the target and is never offered as the port to use.

## Pinned version and how to update it

One place for what is otherwise spread over two scripts:

- **Pin:** `appium-webdriveragent` **16.18.5**. The default is written twice, once per script, and both must stay equal: `scripts/wda-sim.sh` (`WDA_VERSION="${WDA_VERSION:-16.18.5}"`) and `scripts/wda-device.sh` (same line). `WDA_VERSION=<x>` in the environment overrides both for one run.
- **Node:** 16.18.x is fetched with `npm pack`, which runs on the Node in PATH. An unpinned `npm pack` hands out 17.x, which requires Node 22/24/26+ - one reason the pin exists. `rn-devtools.mjs` separately needs Node >= 22.4 (the global `WebSocket`).
- **Where the sources live:** `npm pack` unpacks into `~/.cache/wda-device/package` (`$WDA_DEVICE_HOME`); the simulator runner is built from it as shipped. The scripts never replace an existing checkout of another version - they print a NOTE saying how to switch.
- **The phone's keyboard patch is a script step, not a patch file.** On every version change `wda-device.sh` copies `package` to `package-device`, removes the single line `[FBConfiguration.sharedInstance configureDefaultKeyboardPreferences];` from `WebDriverAgentRunner/UITestingUITests.m` with `sed`, and checks with `grep` that the call is gone - if upstream renamed or moved it, the script exits 1 and says so instead of building a runner that switches the phone's Auto-Correction and Predictive Text off. `WDA_KEEP_KEYBOARD=0` builds upstream's behaviour. Simulators always run upstream's.

To move to another version:

1. Try it without touching anything shared: `WDA_VERSION=<new> WDA_DEVICE_HOME=<empty dir> scripts/wda-sim.sh build`, then `wda-sim.sh ensure <udid> --port <p>` on a disposable simulator (and `wda-device.sh` with the same two variables for a phone - the keyboard step fails loudly if it no longer applies).
2. Measure before and after on the same simulator and screen: `scripts/regress.sh` (output must be identical apart from session ids) and `scripts/simbench.sh` (see `benchmarks.md`).
3. Change the default in BOTH scripts, then remove `~/.cache/wda-device/package`, `package-device` and the `DerivedData*` directories so the next run fetches and builds the pin.
4. Record the measurement in `benchmarks.md`.
